## 1. 이 작업이 답해야 할 질문

**스키마와 ADR이 만들어 둔 개념에 실제로 손이 닿는가?**

지금 넷은 **기록만 되고 볼 수도 바꿀 수도 없다.**

| 개념 | 어디에 있나 | 손이 닿나 |
|---|---|---|
| `books.status = 'needs_review'` | CHECK에 있고 [ADR-014](../../decisions/ADR-014.md)가 넣는다 | **못 본다.** 셰익스피어 전집이 갇혀 있다 |
| `revision_successions.orphan_ids` | 기록되고 부분 인덱스까지 있다 | **못 본다.** 읽기 쿼리 0건 |
| `users.role = 'reviewer'` | CHECK·`CanReview`·`promote`가 전부 준비돼 있다 | **못 만든다.** 역할 변경 쿼리가 없다 |
| `translation_projects.status = 'published'` | CHECK·`published_at`·[ADR-036](../../decisions/ADR-036.md)이 정했다 | **못 옮긴다.** 전이 쿼리가 없다 |

**그래서 이 슬라이스는 화면이 아니라 쿼리가 먼저다.** 슬라이스 7과 정반대다 —
7은 "기존 계약 9개로 성립한다"를 확인하는 것이었고, **8은 계약을 늘리는 것이 본론이다.**

부수적으로 답하는 것:

- **목록 API가 하나도 없는 상태에서 첫 목록을 어떻게 낼 것인가** (`docs/tech-debt.md` D5).
- **읽기 화면(SSR)과 관리자 화면(CSR)이 한 슬라이스 안에서 갈리는가** (ADR-006).

### 이 슬라이스가 답하지 않는 것

- 검색·필터·정렬. 도서 22권이다. **필요해지면 그때 연다.**
- 페이지네이션 (§4.3).
- 용어집 UI (`book_glossary`) — 의도된 미구현 (ADR-010, `tech-debt.md` D6).

## 2. 범위

### 하는 것

- **없는 쿼리를 만든다** — `tech-debt.md` D1·D2·D3·D4·D5
- **`openapi.yaml`에 오퍼레이션을 더한다.** 이번에는 계약을 늘린다 (§4.2)
- **도서 목록 화면** — 공개. **SSR 읽기 화면이다** (§4.7)
- **관리자 확인 큐 화면** — `needs_review` 도서 + 승계 고아. CSR
- **역할 부여** — `member ↔ reviewer`. CSR
- **프로젝트 공개 전이** — `open ↔ published` (ADR-036). CSR

### 하지 않는 것 — 건드리면 안 됨

- **`admin`을 부여하는 경로를 만들지 않는다.** `ADMIN_EMAIL`이 유일한 출처다 (§2 제약).
- **`stable_id` 생성 규칙**([ADR-016](../../decisions/ADR-016.md))**을 건드리지 않는다.**
  고아 목록은 **읽기만** 한다. 고아를 되살리거나 다시 붙이는 조작은 이 슬라이스가 아니다.
- **승인 트랜잭션**([ADR-024](../../decisions/ADR-024.md))**을 건드리지 않는다.**
- **편집·검수 화면을 고치지 않는다.** `...$idx_.edit.tsx`는 그대로 둔다.
- **자동 공개 규칙을 만들지 않는다.** ADR-036이 **관리자가 손으로**로 닫았다.
  커버리지로 자동 공개하고 싶어지면 **먼저 ADR-036을 다시 열어라.**
- **챕터 색인(ADR-023)과 `published`를 엮지 않는다.** 둘은 독립이다 —
  `open`이어도 커버리지 80%를 넘긴 챕터는 색인된다. `published`는 **발견 가능해지는** 문턱이지
  **읽을 수 있어지는** 문턱이 아니다 (ADR-036).
- 새 프론트 의존성. ADR-035가 고정한 것만 쓴다.

### 알고 시작해야 하는 제약

- **`admin`은 부여할 수 없고, 부여해도 소용없다.** `internal/auth/google.go`의 `promote()`가
  로그인마다 역할을 다시 정한다: `fromLogin == admin`이면 admin, 아니면 **기존이 reviewer일 때만**
  reviewer가 살아남는다. 즉 **손으로 올린 `admin`은 다음 로그인에 `member`로 떨어진다.**
  이건 버그가 아니라 ADR-027의 설계다 — `ADMIN_EMAIL`이 admin의 유일한 출처다.
  **`reviewer`는 반대로 로그인해도 살아남는다.** `promote()`가 그러라고 있는 함수다.
- **셰익스피어 전집(100번)이 `needs_review`에 실제로 갇혀 있다.** 챕터 1,684 · 문단 39,354로
  ADR-014의 임계값(챕터 200 / 문단 15,000)을 넘겼다. **큐 화면의 첫 손님이자 유일한 실물 표본이다.**
- **프로덕션에는 번역 프로젝트가 하나도 없다.** 슬라이스 7이 프로덕션에서 제안 → 승인을
  못 돌려본 이유다 (§6에 인계 항목으로 있다).

### 의존성

**새 의존성을 늘리지 않는다.** Go 여섯([ADR-021](../../decisions/ADR-021.md)),
프론트는 ADR-035가 고정한 것. 필요하면 `Proposed` ADR로 남기고 확인할 것.

## 4. 구현 명세

### 4.1 없는 쿼리 — 먼저 만든다

| | 무엇 | 부채 |
|---|---|---|
| 1 | `books` 목록. 상태 필터(`needs_review`) 포함 | D1 · D5 |
| 2 | `revision_successions`에서 `orphaned > 0`인 것 목록 | D2 |
| 3 | `users.role` 변경 | D3 |
| 4 | `translation_projects.status` 전이 (`published_at` 기록) | D4 |
| 5 | `translation_projects` 목록 (도서 목록이 쓴다) | D5 |

`CountBooks`와 `ChapterCoverage`는 **만들어 놓고 안 쓰는 것**이다 (`tech-debt.md` U2).
**이 슬라이스에서 쓰거나, 못 쓰겠으면 왜인지 적어라.**

부분 인덱스 `revision_successions_orphaned (book_id) WHERE orphaned > 0`가 **이미 있다.**
고아 목록 쿼리는 그 인덱스를 타야 한다 — `EXPLAIN`으로 확인하라.

### 4.2 계약부터 — `openapi.yaml`

**AGENTS.md 작업 규칙 5다.** 핸들러를 먼저 고치면 다음 `make generate`에서 덮어써진다.
순서는 `openapi.yaml` → `make generate` → 핸들러 → 화면이고, **산출물까지 커밋한다.**

새 오퍼레이션은 아래를 덮으면 된다. **이름과 모양은 기존 9개의 결을 따르라.**

| 조작 | 성격 |
|---|---|
| 도서 목록 | 공개 |
| 번역 프로젝트 목록 | 공개 |
| `needs_review` 도서 목록 | 관리자 |
| 승계 고아 목록 | 관리자 |
| 역할 부여 | 관리자 |
| 프로젝트 상태 전이 | 관리자 |

**공개 두 개와 관리자 네 개를 섞지 마라.** 관리자 것은 `/admin/` 아래에 둔다 — 기존
`POST /admin/books` · `POST /admin/projects`와 같은 자리다.

### 4.3 목록 계약 — 페이지네이션은 지금 넣지 않는다

도서가 22권이다. **커서도 오프셋도 넣지 않는다.**

다만 **그 판단을 계약에 드러내라.** 나중에 넣을 때 응답 모양이 깨지지 않도록,
목록 응답을 **배열이 아니라 객체로 감싼다**(`{ items: [...] }` 형태). 배열을 그대로 내면
`nextCursor` 하나 붙이는 데 파괴적 변경이 된다.

**이 판단이 이 슬라이스에서 유일하게 ADR감이다.** 목록 계약의 모양은 뒤에 오는 모든 목록이
따르게 된다. `Proposed` ADR로 남기고 확인을 요청하라 (AGENTS.md 작업 규칙 2).

### 4.4 관리자 확인 큐

**두 가지를 한 화면에 둔다.** 성격이 다르니 갈라 보여준다.

- **`needs_review` 도서** — ADR-014의 크기 게이트에 걸린 것. 각 행에 **챕터 수·문단 수와
  임계값(200 / 15,000)을 같이** 보여라. 숫자 없이 "확인 필요"만 뜨면 판단할 수가 없다.
  **지금 할 수 있는 조작은 없다.** 보는 것이 이 슬라이스의 몫이다 — 합본 분할은 ADR-014가
  "나중에 넣는다면 작품 단위로 나눈 뒤에만"이라고 미뤄 뒀다. **여기서 상태를 바꾸는 버튼을
  만들지 마라.** 만들려면 ADR을 먼저 써라.
- **승계 고아** — `orphaned > 0`인 승계 기록. **사람이 쓴 번역이 갈 곳을 잃은 것**이라
  ADR-004 불변식 1이 걸린 자리다. 책·승계 시각·고아 수를 보여준다. 역시 **읽기만** 한다.

### 4.5 역할 부여

- **`member ↔ reviewer`만이다.** `admin`은 목록에도 넣지 마라 (§2 제약).
- 화면에 **"`admin`은 `ADMIN_EMAIL`로만 정해진다"**를 적어라. 안 적으면 다음 사람이
  admin 부여를 찾다가 `promote()`를 고치려 든다.
- **자기 자신의 역할을 내리는 것을 막아라.** 관리자가 스스로를 강등하면 되돌릴 손이 사라진다.
  (실제로는 `ADMIN_EMAIL`이라 다시 로그인하면 복구되지만, **그 복구 경로에 기대지 마라** —
  화면이 사용자를 함정에 빠뜨리지 않는 것이 목적이다.)
- 사용자를 어떻게 찾을 것인가는 열려 있다. 22권 규모의 서비스라 **목록 전체를 내려도 된다.**
  다만 이메일은 개인정보다 — **필요 없으면 응답에 넣지 마라** (`CONVENTIONS.md` 보안).

### 4.6 프로젝트 공개 전이 (ADR-036)

- `open ↔ published`. `archived`도 CHECK에 있으니 계약에 넣을지 정하라.
- **`published_at`은 전이 시각을 기록하고, 내려올 때 비우지 않는다.** ADR-036이 명시했다 —
  "언제 처음 공개됐는가"가 사라지면 복구할 수 없다.
- **`published`의 의미는 하나다: 도서 목록에 노출되는가.** 다른 의미를 붙이지 마라.
- 도서 목록은 `published`만 보여준다. **관리자에게는 `open`도 보여야** 공개할 것을 고를 수 있다.

### 4.7 화면 — SSR과 CSR이 갈리는 지점

**도서 목록은 읽기 화면이다.** ADR-006대로 **SSR + 로더**로 만든다.
**react-query 훅도 shadcn 컴포넌트도 넣지 마라.** 슬라이스 7이 확인한 성질
(읽기 청크 669바이트, API URL 0건)을 그대로 유지해야 한다.

**관리자 화면은 CSR이다.** 편집·검수 화면과 같은 방식 — react-query 훅, shadcn,
뮤테이션 뒤 무효화. 낙관적 갱신은 하지 않는다.

**에러는 삼키지 않는다.** 401은 로그인 안내, 403은 조작을 애초에 렌더하지 않는다.
화면이 권한을 판정하지 않는다 — 서버가 판정하고 화면은 반영할 뿐이다.

### 4.8 테스트

- **Go**: 새 관리자 오퍼레이션마다 **비로그인 401 · 비관리자 403 · 관리자 200**을 확인한다.
  `internal/api/server_test.go`에 이미 그 표가 있다 — **같은 자리에 줄을 더하라.**
- **Go**: 역할 부여 후 **재로그인해도 `reviewer`가 살아남는 것**을 확인한다 (`promote()`).
  이것이 D3가 닫혔다는 증거다.
- **Go**: `published → open`으로 내려도 **`published_at`이 남는 것**을 확인한다 (ADR-036).
- **web**: `DATABASE_URL` 없이 돈다. 관리자 조작이 권한 없으면 렌더되지 않는 것.
- **web**: **도서 목록이 `published`만 보여주는 것.**

## 5. 반드시 지킬 것

1. **`internal/api/auth.go`의 `authedOperations`와 `adminOperations`에 새 오퍼레이션을 넣어라.**
   그 파일의 주석이 이미 경고한다 — **"여기 넣는 것을 잊으면 무인증으로 열린다."**
   `openapi.yaml`의 `security` 선언과 **두 곳이 따로 논다.** 한쪽만 고치면
   **테스트도 빌드도 배포도 전부 성공하고 관리자 API가 세상에 열린다.**
   §4.8의 401/403/200 표가 이걸 잡는 유일한 그물이다. **오퍼레이션마다 줄을 더하라.**
2. **`web/eslint.config.js`의 가드 `files` 목록에 새 읽기 라우트를 추가하라.**
   목록은 파일 이름을 하나씩 적는 방식이라 **새 라우트는 자동으로 안 덮인다.**
   빠뜨리면 도서 목록에 react-query가 들어가도 아무도 못 잡는다 —
   **그리고 SSR은 멀쩡해 보여 배포가 성공으로 찍힌다** (ADR-035).
3. **`openapi.yaml`부터 고치고 `make generate`를 돌려라** (작업 규칙 5). 산출물까지 커밋한다.
4. **`published_at`을 비우지 마라** (ADR-036).
5. **`admin` 부여 경로를 만들지 마라** (ADR-027).
6. **고아 번역을 읽기만 하라.** 되살리는 조작은 `stable_id` 규칙(ADR-016)에 닿는다 —
   이 프로젝트에서 가장 되돌리기 어려운 자리다.
7. 작업 종료 전 `make lint && make test && make docs-check` 통과. **`DATABASE_URL` 없이도** web 테스트 통과.
