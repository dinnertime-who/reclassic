# ADR-028 — Cloudflare(D1 + Workers) 이전을 검토하고 현행 스택을 유지한다
**상태:** Accepted (2026-08-20). ADR-001·002·003을 재확인한다 — 뒤집지 않는다.

**맥락:** 운영 편의성 때문에 스택 전환을 검토했다. Cloudflare 대시보드가 손에 익어
인프라를 한곳에서 보고 싶다는 동기였고, R2를 이미 쓰고 있으니(ADR-008) 자연스러운 생각이다.
D1을 DB로, Workers를 런타임으로 쓰면 백엔드가 Node/TS가 되고 프론트와 언어가 통일된다.

**검토 결과 — D1로 가면 불변식 둘이 깨진다.**

1. **트랜잭션 안 잡 등록이 불가능하다.** ADR-003이 Redis 대신 River를 고른 **유일한 근거**이고,
   `TestRequestRollsBackBookWhenEnqueueFails`가 지키고 있다.
   Cloudflare Queues는 D1 트랜잭션에 참여하지 않으므로
   "책은 생성됐는데 잡 등록이 실패"하는 틈이 그대로 돌아온다.
2. **D1에 대화형 트랜잭션이 없다.** 원자적 `batch()`만 있고 중간에 읽어서 분기할 수 없다.
   승인 트랜잭션(불변식 3)은 읽고 → 판단하고 → 세 번 쓰는 구조라 그대로 옮겨지지 않는다.
   `pg_advisory_xact_lock`도 없어 **ADR-024를 다른 방식으로 다시 풀어야 한다** —
   40라운드 반복에서야 드러난 버그였다.

그 밖에 걸리는 것: 셰익스피어 7MB를 Worker 128MB에서 파싱해야 하는데
전략 체인이 트리 순회(`Find`/`Closest`/clone-remove)라 스트리밍 `HTMLRewriter`로는 안 되고,
`COPY` 39,355행이 배치 문장 제한에 걸려 여러 왕복으로 쪼개진다.

**결정:** 현행을 유지한다. Go + Railway + Postgres + River.

**남겨 두는 선택지 — 안 C.** 운영 편의성이 실제로 아프면 **D1 없이** Cloudflare로 갈 수 있다:
Workers + Hyperdrive + 관리형 Postgres(Neon 등) + `graphile-worker`/`pg-boss`.
두 큐 모두 트랜잭션 안 enqueue를 지원하므로 ADR-003이 살고 자문 잠금도 그대로 쓴다.
스키마는 거의 손대지 않고 애플리케이션 ~5,300줄만 옮기면 된다.
파서는 `cheerio`가 goquery와 API 계보가 같아 가장 순하게 옮겨지는 축이다.

**결과:**

- **이 검토를 다시 하지 않는다.** 다시 열 이유는 "운영이 실제로 아파서"여야지
  "Cloudflare를 써보고 싶어서"가 아니다.
- **배포 슬라이스를 먼저 해보고 판단하는 것이 옳다.** 지금 운영 부담은 추정이고,
  Railway 4서비스가 실물로 돌아본 적이 없다. 아프다는 것이 확인되면 안 C를 꺼낸다.
- 전환하기로 하면 **D1이 아니라 안 C**다. 위 둘을 다시 푸는 비용이 이전 이득보다 크다.
