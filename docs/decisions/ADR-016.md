# ADR-016 — 반복 본문의 `stable_id` 충돌은 등장 순서로 분리한다
**상태:** Accepted (2026-08-19). ADR-004를 보완한다 — 뒤집지 않는다.

**맥락:** ADR-004는 `stable_id = sha256(정규화 본문)[:16]`으로 정의했고,
`paragraph_translations`의 PK는 `(project_id, paragraph_stable_id)`다(ADR-005).
해시 입력이 본문뿐이므로 **본문이 같은 문단은 책의 서로 다른 위치에 있어도 번역 행 하나를 공유한다.**
제안(`translation_proposals`)도 같은 키를 쓰므로 제안·검수·읽기 화면이 모두 함께 묶인다.

스파이크 재검증에서 규모가 확인됐다. 파서의 더블카운팅이 아니라 원문에 실제로 반복되는 문장이다
(발생 위치가 전부 다른 챕터·인덱스).

| 권 | 총 문단 | 자리를 잃는 문단 | 비율 |
|---|---|---|---|
| 100 Shakespeare | 39,354 | 2,136 | 5.4% |
| 1524 Hamlet | 1,376 | 67 | 4.9% |
| 345 Dracula | 1,945 | 64 | 3.3% |
| 1661 Sherlock Holmes | 2,523 | 42 | 1.7% |
| 98 A Tale of Two Cities | 3,259 | 53 | 1.6% |
| 4300 Ulysses | 7,064 | 72 | 1.0% |

22권 중 6권은 중복이 0이다. 중복의 거의 전부가 60자 이하 짧은 대사다.

**결정:** 같은 본문의 **첫 등장은 지금과 동일하게** `sha256(text)`를 쓰고,
2번째 이후만 등장 순서를 붙인다.

```
n = 1  →  stable_id = sha256(normalized)[:16]              (현행과 완전히 동일)
n ≥ 2  →  stable_id = sha256(normalized + "#" + n)[:16]
```

순서 부여는 **파서 후처리 단계**에서 한다(ADR-013 후처리 뒤, 챕터·문단 순서가 확정된 시점).
`Normalize`에는 넣지 않는다 — 앞선 문단을 알아야 하므로 순수 함수가 깨지기 때문이다
(SPIKE_PARSER §5.7의 "정규화 함수는 순수 함수여야 한다"를 유지).

---

### 왜 안 C인가 — 검토한 세 안

**안 A(현행 유지, 충돌 허용) — 기각.** 제품 결정이다.
영어 `"Yes."`는 화자와 상대에 따라 `"네."` / `"그래."` / `"예, 그렇습니다."`로 달라져야 하는데,
행이 하나뿐이면 **같은 원문이 나오는 모든 자리에 같은 존댓말이 강제된다.**
번역자가 화자별로 다르게 옮길 방법이 아예 없다.
용어 일관성은 `book_glossary`가 담당하므로(ADR-010), 대사까지 강제로 통일할 이유가 없다.

**안 B(위치를 해시에 포함, `sha256(chapter_idx + para_idx + text)`) — 기각.**
충돌은 사라지지만 **ADR-004의 존재 이유를 스스로 무효화한다.**
ADR-004는 "재파싱하면 문단 행 ID가 밀린다"를 풀려고 만들어졌는데,
안 B는 위치를 해시에 넣어 "밀리면 깨진다"를 되살린다. `paragraphs.id`를 참조하는 것과 실질적으로 같고,
FK 무결성만 포기하고 얻는 것이 없다.

이건 이론이 아니라 당장 닥친다. **ADR-013(빈 챕터 제거)을 적용했을 때 기존 id 생존율**을
코퍼스 22권으로 시뮬레이션한 결과:

| | 안 B 생존 | 안 C 생존 |
|---|---|---|
| **22권 평균** | **32.5%** | **100.0%** |
| 84 Frankenstein (빈 챕터 28) | 0.3% | 100% |
| 345 Dracula (27) | 0.1% | 100% |
| 100 Shakespeare (842) | 0.0% | 100% |
| 1524 Hamlet (20) | 0.0% | 100% |
| 76 Huckleberry Finn (44) | 0.0% | 100% |
| 1400 Great Expectations (0) | 100% | 100% |

15권에서 거의 전멸한다. 100% 생존한 7권은 빈 챕터가 0이라 아무것도 밀리지 않은 책들뿐이다 —
즉 안 B가 살아남는 조건은 "파서 결과가 하나도 안 바뀐 경우"다.
챕터 하나만 지워져도 뒤따르는 모든 챕터의 `chapter_idx`가 밀리고, 그 안 모든 문단의 id가 바뀐다.
지역적 변경이 전역적 id 변경으로 증폭된다.

부작용이 하나 더 있다. 안 B에서는 본문이 한 글자도 안 바뀌어도 위치만 밀리면 해시가 달라지므로,
ADR-004의 revision 전환 규칙에서 **"해시 일치 → 자동 승계"가 사실상 발동하지 않고**
전부 관리자 확인 큐로 쏟아진다. 위대한 유산이면 3,833건, 셰익스피어면 39,354건이다.
큐가 예외 처리용이 아니라 주 작업이 된다.

**안 C(반복분에만 등장 순서) — 채택.**
해시 입력이 본문뿐이라 위치가 아무리 밀려도 본문이 같으면 id가 같다. 위 시뮬레이션에서 100% 생존한다.
첫 등장의 id를 바꾸지 않으므로 **중복 없는 문단(대다수)과 중복 0인 6권은 영향이 전혀 없다.**
충돌 위험은 "같은 본문을 가진 문단들" 안으로 갇힌다.

**결과:**

- 문단당 확정본 1개(불변식 2)와 재파싱 안전성(불변식 1)을 둘 다 유지한다.
- `paragraph_translations` / `translation_proposals`의 스키마는 바뀌지 않는다.
  `stable_id`를 만드는 규칙만 바뀐다.
- **남는 위험:** 같은 본문의 반복 사이에 새 반복이 끼어들면 뒤쪽 순서가 밀린다.
  드라큘라 `"Jonathan Harker's Journal."` 9회 중 앞쪽에 하나가 새로 잡히면 뒤 8개가 +1 된다.
  영향이 그 텍스트에만 갇히고 건수도 작아서, ADR-004의 "유사 → 관리자 확인 큐"가 받아낸다.
- 본문 자체가 바뀌면(예: ADR-013의 이미지 이니셜 복원 56문단) 어떤 방식으로도 id가 바뀐다.
  이는 ADR-004가 설계상 받아내기로 한 부분이다.
- 구현: `internal/parse/postprocess.go`의 `assignOccurrenceIDs`. `Normalize`는 순수 함수로 그대로다.
