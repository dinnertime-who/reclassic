# ADR-027 — 인증은 Google 위임, 세션은 Postgres 테이블, 관리자는 지정 계정
**상태:** Accepted (2026-08-20). `AGENTS.md`가 열어둔 "인증 방식 세부"를 닫는다.

**맥락:** 슬라이스 4에서 역할(`member|reviewer|admin`)과 권한 검사를 만들었지만
신원이 `X-User-Handle` 헤더였다. 헤더 하나로 검수자를 사칭할 수 있으니
권한 체계 전체가 모래 위에 있었다. 문서 세 곳이 이 때문에 프로덕션 배포를 금지하고 있었다.

**결정 셋:**

### 1. 로그인은 Google OAuth만

- **비밀번호를 다루지 않는다.** 해싱·재설정·유출 대응·크리덴셜 스터핑 방어가 전부 사라진다.
  1인 운영에서 이만한 절약이 없다.
- 다른 제공자를 넣지 않는다. 필요해지면 그때 추가한다.
- **ID 토큰(JWT)을 직접 검증하지 않는다.** 코드 교환이 서버 대 서버 TLS이므로,
  받은 액세스 토큰으로 userinfo를 한 번 부르면 된다.
  JWKS 캐싱과 서명 검증을 들이지 않는 만큼 틀릴 여지가 준다.
- **사용자 식별은 `google_sub`이다. 이메일이 아니다.** 이메일은 바뀌고,
  Google이 재사용하지 않는다고 보장하는 것은 `sub`뿐이다.

### 2. 세션은 Postgres 테이블

- **즉시 회수가 가능해야 한다.** 검수 권한이 있는 서비스에서 "이 계정 지금 끊어라"가
  안 되면 사고가 났을 때 할 수 있는 게 없다.
- **토큰을 평문으로 저장하지 않는다. sha256만 저장한다.**
  DB가 유출돼도 그 값으로 로그인할 수 없다. 비밀번호와 같은 이유다.
- 쿠키는 `HttpOnly` + `SameSite=Lax`. `Secure`와 `Domain`은 환경변수로 제어한다 —
  로컬 http에서는 `Secure`를 꺼야 붙는다. **프로덕션에서 켜는 것을 잊지 말 것.**
- 수명 30일, 갱신 없음.

**서명 쿠키(JWT)를 기각한 이유:** DB 조회가 없어 빠르지만 만료 전에 무효화할 수 없다.
권한을 빼거나 계정을 정지해도 토큰이 살아 있다. 무효화 목록을 두면 결국 테이블이 생기고,
그때는 "빠르다"는 장점도 사라진다.

### 3. 관리자는 지정된 Google 계정

`ADMIN_EMAIL`과 일치하는 계정으로 로그인하면 `admin`이 된다.

- **매 로그인마다 다시 판정한다.** 환경변수에서 빼면 다음 로그인에 권한이 사라진다.
- Google이 `email_verified: true`를 준 경우에만 대조한다.
- 비어 있으면 기동 실패. 관리자가 아무도 없는 배포는 사고다.
- 손으로 올려준 `reviewer`는 로그인해도 `member`로 내려가지 않는다.
  다만 `admin`은 `ADMIN_EMAIL`이 유일한 출처다.

**별도 비밀번호 관리자 계정을 두지 않은 이유:** Google 장애 시 비상구가 생기지만,
로그인 경로가 둘이 되고 비밀번호 해싱·변경 흐름이 되살아난다.
이 프로젝트 규모에서 비상구의 값어치보다 표면적이 크다.
정말 막히면 SQL로 `role`을 바꾸면 된다 — DB 접근은 어차피 필요하다.

**임시 장치 제거 — 우회로를 남기지 않는다:**

- `X-User-Handle` 삭제 (슬라이스 4의 임시 신원)
- `X-Admin-Token`과 `ADMIN_TOKEN` 삭제 (ADR-026 시점의 임시 운영 가드).
  관리자 엔드포인트는 이제 세션 + `role='admin'`이다.
- ADR-026의 CORS `AllowedHeaders`에서도 뺐다. 남은 것은 `Content-Type`뿐이다.

**둘 중 하나라도 남기면 인증을 붙인 의미가 없다.** 실제로 구 헤더로 호출해 401을 확인했다.

**결과:**

- 런타임 직접 의존성이 여덟이 된다 (`golang.org/x/oauth2` 추가).
- **OAuth 리다이렉트 엔드포인트(`/auth/google/*`)는 `openapi.yaml`에 넣지 않는다.**
  JSON을 주고받지 않고 브라우저가 직접 이동하는 302라, 계약에 넣어도 생성기가
  쓸모없는 클라이언트를 만들 뿐이다. 라우터에 직접 단다.
  `/auth/me`와 `/auth/logout`은 JSON이라 계약에 있다.
- 로그인 성공 후 돌아갈 웹 주소(`LOGIN_SUCCESS_REDIRECT`)와 로그인 시작 주소
  (`VITE_LOGIN_URL`)를 환경변수로 둔다. 웹과 API가 다른 출처라 하드코딩할 수 없다.
- **읽기 화면은 비로그인도 볼 수 있다.** 로그인이 필요한 것은 제안·검수·관리뿐이다.
  세션 미들웨어는 사용자를 컨텍스트에 싣기만 하고, 거부는 오퍼레이션별로 한다.
