# ADR-036 — 번역 프로젝트의 공개는 관리자가 손으로 한다
**상태:** Accepted (2026-08-25). `AGENTS.md`가 열어 둔 "번역 프로젝트 전체의 공개 기준"을 닫는다.

**맥락:** `translation_projects.status`에 `open` / `published` / `archived` CHECK가 있고
`published_at` 컬럼도 있는데, 쿼리는 `CreateProject` 하나뿐이라 **`published`로 가는 경로가 없다.**
스키마가 개념을 만들어 두고 코드가 비어 있는 상태다 (`docs/tech-debt.md` D4).

챕터 단위 색인은 ADR-023이 승인 커버리지 80%로 정했다. **프로젝트 전체의 공개는 그와 별개 결정으로
남아 있었고**, `AGENTS.md`의 "열려 있는 질문"에 유일하게 남은 항목이었다.

**결정:** **관리자가 손으로 `open → published`로 옮긴다. 자동 규칙을 두지 않는다.**

`published`의 의미도 여기서 정한다 — **도서 목록에 노출되는가.** 그것 하나다.

**챕터 색인(ADR-023)과는 독립이다.** 프로젝트가 `open`이어도 커버리지 80%를 넘긴 챕터는
색인되고 사이트맵에 들어간다. 확인했다: `ListProjectChapterCoverage`와 사이트맵 잡은
`translation_projects.status`를 보지 않는다. 즉 **`published`가 아니어도 URL을 아는 사람은 읽을 수 있다.**
`published`는 "발견 가능해지는" 문턱이지 "읽을 수 있어지는" 문턱이 아니다.

**대안과 기각 사유:**

- **커버리지로 자동 공개** (예: 색인 대상 챕터가 N% 이상이면 자동 `published`) —
  ADR-023과 결이 같아 자연스러워 보인다. 기각한 이유는 **임계값을 정할 근거가 지금 없다**는 것이다.
  ADR-023의 80%는 "부분 공개를 허용한다"는 판단에서 나왔고 **챕터 단위라 틀려도 되돌리기 쉽다.**
  프로젝트 공개는 더 무겁다. 운영 데이터가 없는 상태에서 숫자를 박으면 그 숫자가 근거 없이 굳는다.
  **자동화는 언제든 나중에 얹을 수 있지만, 잘못 박은 임계값은 걷어내기 어렵다.**
- **`published`를 쓰지 않는다** (챕터 색인만으로 충분하다고 보고 `open`/`archived`만 사용) —
  기각한다. 도서 목록을 만드는 순간 **"이 번역은 남에게 보여도 되는가"를 담을 자리가 반드시 필요해진다.**
  CHECK와 `published_at`이 이미 있으므로 새로 만드는 것도 아니다.

**결과:**

- **상태 전이 API와 쿼리가 필요하다.** 이 슬라이스(7)가 아니라 **도서 목록을 만드는 슬라이스 8**에서 만든다.
  지금 만들면 쓰는 화면이 없다.
- **`published_at`은 전이 시각을 기록한다.** `published`에서 내려올 때(다시 `open`이나 `archived`로)
  비우지 않는다 — "언제 처음 공개됐는가"가 사라지면 복구할 수 없다.
- **되돌릴 수 있는 결정이다.** 운영하면서 "이쯤이면 공개"라는 기준이 눈에 보이면 그때 자동화하고
  이 ADR을 다시 연다. 반대 방향(자동 → 수동)이 훨씬 비싸다.
- `AGENTS.md`의 "열려 있는 질문" 절이 비게 된다.
