# ADR-040 — 읽기 설정은 쿠키에 담고, 읽기 라우트에 스크립트를 처음 허용한다
**상태:** Accepted (2026-09-03). [ADR-035](ADR-035.md)의 "읽기 라우트는 로더 + 순수 HTML"을 갱신한다.

**맥락:** 읽기 좋은 크기는 사람마다, 기기마다, 조명마다 다르다. 전자책 서비스가 예외 없이
글자 크기·행간·여백 조절을 갖는 이유다. 우리 읽기 화면에는 그것이 없고, 지금은 조절할 방법도 없다.

막고 있던 것은 ADR-035가 그어 둔 선이다 — *"읽기 라우트는 지금의 로더 + 순수 HTML을 유지한다."*
그 선의 근거는 [ADR-007](ADR-007.md)·[ADR-023](ADR-023.md)의 SEO 전제인데, **그 전제가 실제로
요구하는 것은 "본문이 자바스크립트 없이 HTML에 담겨 온다"이지 "스크립트를 두지 않는다"가 아니다.**
크롤러가 전문을 받고 첫 페인트가 JS 없이 끝나면 전제는 지켜진다.

**결정:**

**1. 조절 항목은 셋, 전부 단계다.** 글자 크기 5단계 · 행간 3단계 · 좌우 여백 3단계.
연속 슬라이더로 두지 않는다 — 자유롭게 끌면 제목과 본문의 비율이 무너져 타입 스케일이 깨진다.
읽기 방식은 **스크롤로 고정한다.** 페이지 넘김은 이 결정의 범위가 아니다.

**2. 저장은 쿠키다. 계정이 아니라 기기에 붙는다.**

**3. 서버가 SSR에서 쿠키를 읽어 `<html>`에 CSS 변수를 얹는다.** 첫 페인트부터 사용자의 값이다.

**4. 읽기 라우트에 작은 바닐라 스크립트 하나를 허용한다.** 값을 바꾸면 즉시 반영하고 쿠키를 다시 굽는다.

**왜 DB가 아니라 쿠키인가:**

- **읽는 사람 대부분이 비로그인이다.** 읽기 화면은 공개다. 계정에 묶으면 다수가 못 쓴다.
- **읽기 좋은 크기는 기기마다 다르다.** 폰과 데스크톱이 같아야 할 이유가 없다 —
  계정에 묶으면 오히려 한쪽이 틀린다.
- **서버가 SSR에서 읽을 수 있는 유일한 저장소다.** 이것이 결정적이다.

**쿠키 규격:** 이름 `reclassic_reader`, 값은 단계 번호만 담는 고정 폭 문자열.
`HttpOnly`는 **아니다** — 클라이언트가 써야 한다. 비밀이 들어가지 않으므로 그래도 된다.
`SameSite=Lax` · 프로덕션 `Secure` · `Max-Age` 1년 · `Path=/`.

**절대 깨지 말 것 — 쿠키 값을 CSS에 그대로 넣지 않는다.** 쿠키는 사용자가 마음대로 쓰는 값이다.
서버는 단계 번호를 **허용 목록으로 좁혀** 미리 정해 둔 값에만 매핑한다. 문자열을 `style` 속성에
이어 붙이면 **CSS 주입**이 된다. 단계를 유한하게 둔 이유의 절반이 이것이다.

**대안과 기각 사유:**

- **DB에 계정별로 저장한다** — 기기를 옮겨도 따라온다. 기각한다. 비로그인이 못 쓰고, 기기 차이를
  담지 못한다. **로그인 사용자에게 계정 동기화를 나중에 얹는 것은 열려 있다** — 쿠키가 먼저다.
- **`localStorage`에 담는다** — 서버가 관여하지 않아 가장 단순하다. 기각한다. 서버가 읽지 못해
  첫 페인트가 기본값으로 그려지고 **글씨 크기가 한 번 튄다.** 읽기 화면에서 그것이 가장 눈에 띈다.
- **쿠키 + 폼 POST만 쓰고 스크립트를 두지 않는다** — ADR-035의 선을 지킬 수 있다. 기각한다.
  단계를 한 칸 옮길 때마다 페이지가 다시 뜬다. 몇 번씩 누르는 조작에 맞지 않는다.
  **다만 스크립트가 없는 환경에서도 이미 저장된 쿠키는 그대로 먹는다** — 설정이 사라지지 않는다.

**결과:**

- ADR-035의 선 가운데 **스크립트 금지만 풀린다.** 남는 것 둘: **본문은 SSR HTML에 담겨 JS 없이
  렌더된다**, 그리고 **react-query 훅·shadcn 컴포넌트는 여전히 금지다.** ESLint 가드는 그대로 둔다.
- **읽기 HTML이 이제 읽는 사람마다 다르다.** 지금은 HTML을 캐시하지 않으므로(ADR-034) 문제가 없다.
  **HTML 캐시를 켜는 순간 이 쿠키가 `Vary` 대상이 된다** — 켤 때 같이 봐야 한다. tech-debt에 적는다.
- 읽기 라우트 청크의 기준선이 올라간다. 슬라이스 7·8이 재 온 수치(669·186·836바이트, react-query
  0건)는 계속 재되, **스크립트 몫만큼 새 기준을 적는다.** react-query가 0건인 것은 그대로 확인한다.
- 테마(주간·야간)는 이 결정에 넣지 않았다. 인접하지만 별개이고, tech-debt S2에 남아 있다.
