# ADR-043 — 접근성이 걸린 위젯은 읽기 화면에서도 shadcn을 쓴다
**상태:** Accepted (2026-09-04). [ADR-035](ADR-035.md)의 "읽기 화면에 shadcn을 들이지 않는다"와
[ADR-040](ADR-040.md)이 그것을 다시 확인한 문장을 **부분적으로 뒤집는다.**

**맥락:** ADR-040으로 읽기 설정을 만들면서, 시트를 손으로 지었다. `role="dialog"`와
`role="radiogroup"`을 직접 쓰고 Esc·바깥 클릭·포커스 복귀를 `useEffect`로 붙였다.
읽기 화면에 shadcn을 들이지 않는다는 규칙을 지키려면 그 방법뿐이었기 때문이다.

**그런데 규약이 같은 자리에서 서로 반대를 말하고 있었다.** "읽기 화면에 shadcn 컴포넌트를 넣지
않는다"(ADR-035)와 "컴포넌트는 shadcn/ui에 있는지 먼저 찾고, 없을 때만 직접 만든다"가 나란히
있었고, 시트는 shadcn에 있다.

손으로 만든 다이얼로그가 실제로 책임져야 하는 것은 길다 — 포커스 트랩, 열릴 때 초점 이동,
닫힐 때 초점 복귀, 배경 `inert`, 스크롤 잠금, Esc, 바깥 클릭, `aria-modal`, 라벨 연결.
**그중 하나가 빠져도 화면은 멀쩡해 보이고 테스트도 통과한다.** 이 저장소가 반복해서 경계해 온
"조용히 깨지는" 유형이고, 접근성은 그 유형이 가장 자주 나는 자리다.

**결정:** **접근성 동작이 붙는 위젯(다이얼로그·시트·팝오버·메뉴·탭 등)은 읽기 화면에서도
shadcn을 쓴다.** 손으로 다시 만들지 않는다.

**남는 금지 둘은 그대로다:**

1. **react-query 훅은 여전히 읽기 라우트에 넣지 않는다.** 데이터는 로더가 가져온다 (ADR-035).
2. **본문은 SSR HTML에 담겨 자바스크립트 없이 렌더돼야 한다** (ADR-007·023).
   위젯은 그 위에 얹는 것이고, 스크립트가 없으면 **버튼이 아무 일도 하지 않을 뿐 본문은 보인다.**

**대안과 기각 사유:**

- **손으로 계속 만든다** — 읽기 청크가 작게 유지된다. 기각한다. 위에 적은 목록을 우리가 영원히
  맞춰야 하고, 틀렸을 때 아무것도 알려주지 않는다. **번들 몇십 KB보다 비싼 실패다.**
- **설정을 별도 라우트로 빼고 거기서만 shadcn을 쓴다** — 읽기 청크를 건드리지 않는다.
  기각한다. 시트를 열어 둔 채 글자 크기를 바꾸며 **본문이 어떻게 보이는지 확인하는 것**이 이
  화면의 쓰임인데, 화면을 갈아타면 그게 사라진다.
- **접근성까지 포함해 우리 프리미티브를 만든다** — 통제권이 가장 크다. 기각한다.
  shadcn을 이미 쓰고 있으면서 같은 것을 두 벌 유지할 이유가 없다.

**결과:**

- **읽기 라우트 청크가 커진다.** 지금 번역 읽기 청크는 **2,245B**이고, 이미 관측된 Radix 기반
  청크(`alert`)는 **29,150B**다. 시트가 붙으면 그 자릿수로 올라간다.
  **정확한 수치는 `feat/reader-settings-sheet`가 머지될 때 측정해 여기 적는다.**
  슬라이스 7·8이 재 온 "react-query 0건·API URL 0건"은 계속 재고, **크기 기준선만 새로 잡는다.**
- ESLint의 읽기 화면 가드는 **react-query만 남기고** shadcn 항목을 뺀다.
  가드가 규칙과 어긋난 채로 남으면 다음 사람이 규칙 대신 가드를 믿는다.
- 새 shadcn 컴포넌트를 넣을 때는 그것이 쓰는 토큰이 `styles.css`에 있는지 먼저 본다.
  `sheet`이 `bg-popover`를 쓰는데 `--popover`가 없었다 — **그대로 두면 배경이 해석되지 않은 채
  렌더되고 빌드는 성공한다** (`CONVENTIONS.md` "TypeScript / 웹").
- **이 결정은 위젯에만 적용된다.** 읽기 화면의 본문 리듬(타이포·여백·측정폭)은 계속
  `styles.css`의 시맨틱 클래스가 갖는다 (ADR-038). shadcn으로 본문을 짓지 않는다.
